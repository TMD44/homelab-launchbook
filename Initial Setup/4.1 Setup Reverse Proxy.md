# Setup Reverse Proxy

This chapter builds the private HTTPS gateway for the homelab. Traefik routes friendly hostnames to services, CrowdSec analyzes traffic and supplies request protection, and Authelia adds centralized two-factor authentication where it is compatible. When the chapter is complete, supported LAN services will open through trusted HTTPS addresses without making them public.

This is one of the most technically demanding Initial Setup chapters and one of the foundation's most important parts. The work is divided into small checkpoints, so a beginner can complete it successfully by following the order carefully and stopping whenever a required check fails.

## About the Reverse Proxy Stack

A reverse proxy is the single HTTPS front door that receives a hostname such as `komodo.<MY-DOMAIN>.com` and forwards the request to the matching private service. Traefik is the reverse proxy in this design. CrowdSec and Authelia are complementary security services, not additional reverse proxies.

### Traefik

[Traefik Proxy](https://doc.traefik.io/traefik/) provides the HTTP-to-HTTPS redirect, certificate automation, hostname routing, and reusable request middleware. It was selected because its file provider fits services distributed across separate LXC containers. The tradeoff is that routing through one proxy creates a shared dependency: if Traefik is unavailable, the friendly HTTPS routes are unavailable even when their backends still run.

### CrowdSec

[CrowdSec](https://docs.crowdsec.net/) provides a local Security Engine, Local API, community decision feed, and AppSec request inspection. Traefik's JSON access log is parsed locally and raw logs are not uploaded. Eligible security signals can send limited event metadata to CrowdSec's [Central API](https://docs.crowdsec.net/docs/central_api/intro/), and CrowdSec can receive community blocklists. Enrollment in CrowdSec Console is a separate, optional integration.

### Authelia

[Authelia](https://www.authelia.com/) is the identity and authorization service for compatible browser routes. This deployment uses a local user database, TOTP, SQLite state, and file-based secrets. Authelia improves access control but does not replace application authorization or make a service safe for public exposure.

## Understand the Reverse Proxy Architecture

This section explains the concepts and request paths used by the later configuration. It is not another installation procedure.

### Why This Homelab Uses a Reverse Proxy

Without a reverse proxy, each application has a different IP address, port, certificate, and access-control method. The private wildcard DNS rewrite created in the [Custom Domain](<4.0 Setup custom domain.md>) chapter instead sends homelab hostnames to `192.168.0.102`, where Traefik applies one routing and HTTPS policy.

Cloudflare remains the authoritative DNS provider and answers the temporary DNS-01 validation records used to issue the wildcard certificate. Normal application requests do not pass through Cloudflare in this design: public DNS does not route these private hostnames to the homelab, Cloudflare proxying is not enabled, and the router does not forward inbound ports `80` or `443`.

### How a Request Reaches a Service

The normal request path is:

```text
LAN or approved VPN client
          |
          | private DNS lookup
          v
AdGuard Home wildcard rewrite → 192.168.0.102
                                      |
                                      | HTTP redirects to HTTPS
                                      v
                                   Traefik
                                      |
                                      | selected ordered middleware chain
                                      | Authelia participates only with secured-auth
                                      v
                              backend in its own LXC
                                      |
                                      v
                                   response
```

CrowdSec has two separate data paths:

```text
Traefik JSON access log → CrowdSec Security Engine → Local API decisions
                                                       |
                                                       v
                                              Traefik bouncer cache

Eligible request → Traefik CrowdSec plugin → CrowdSec AppSec → immediate verdict
```

Reading the access log supplies asynchronous detection data; it is not the real-time WAF path. AppSec is the synchronous inspection path and can block a request before the backend sees it. Authelia participates only when the route uses ForwardAuth.

This remains a local-only design. The IP allowlist rejects clients outside the approved LAN and VPN ranges, so community-IP remediation has a narrower role than on an Internet-facing proxy. Permitted clients are not also placed in the plugin's `clientTrustedIPs`, so their eligible requests still reach CrowdSec and AppSec.

### How Traefik Routes Requests

Traefik has two configuration layers:

| Layer | Repository file or directory | Purpose | Apply behavior |
| --- | --- | --- | --- |
| Startup configuration | `/TRAEFIK/config/traefik.yaml` | Entry points, redirect, dashboard, logging, file provider, ACME, and plugin version | Recreate or restart Traefik |
| Routing configuration | `/TRAEFIK/config/dynamic/*.yaml` | Routers, services, middleware, and TLS options | File provider hot-reload |

The `web` and `websecure` entry points listen on ports `80` and `443`. A router matches the requested hostname and optional path. Its ordered middleware runs before a service uses a load balancer and backend URL to identify the destination. TLS terminates at Traefik, so a backend can use HTTP on the trusted LAN; the narrowly named `skipverify` transport is used only for current self-signed HTTPS backends.

The [file provider](https://doc.traefik.io/traefik/providers/file/) is deliberate. Applications live in separate LXC containers and are reached by private backend URLs, so Traefik does not need Docker container discovery or a Docker-socket mount. See Traefik's [configuration overview](https://doc.traefik.io/traefik/getting-started/configuration-overview/), [router reference](https://doc.traefik.io/traefik/reference/routing-configuration/http/routing/router/), [middleware reference](https://doc.traefik.io/traefik/reference/routing-configuration/http/middlewares/overview/), and [ACME reference](https://doc.traefik.io/traefik/reference/install-configuration/tls/certificate-resolvers/acme/) for the upstream model.

### How the Middleware Chains Work

Chains give every route the same reviewed order without copying six middleware names into every router.

| Position | `secured` | `secured-auth` | Purpose |
| --- | --- | --- | --- |
| 1 | `private-clients` | `private-clients` | Permit `192.168.0.0/24` and no-SNAT Tailscale addresses in `100.64.0.0/10` |
| 2 | `crowdsec` | `crowdsec` | Enforce Local API decisions and synchronously consult AppSec |
| 3 | `security-headers` | `authelia` | Add safe shared response headers, or ask Authelia to authorize first |
| 4 | `rate-limit` | `security-headers` | Limit bursts, or add the shared headers after authorization |
| 5 | `in-flight` | `rate-limit` | Bound simultaneous requests, or apply the rate limit |
| 6 | - | `in-flight` | Bound simultaneous requests |

`secured` does not add a user login. Use it for applications with their own authentication and for APIs, webhooks, native clients, or token-based integrations that an interactive redirect may break. The Authelia portal uses this chain so it cannot create an authentication loop.

`secured-auth` adds [Authelia ForwardAuth](https://www.authelia.com/integration/proxies/traefik/). Traefik asks Authelia whether the original request is authorized, then either continues to the backend or returns Authelia's denial or login redirect. Use it only for a compatible browser route that also has an explicit Authelia access-control rule; do not rely on a blanket wildcard authorization policy.

The CrowdSec plugin sends at most `10 MiB` of a body to AppSec. If a streaming body cannot be buffered, it sends headers only and leaves the body stream untouched. AppSec server errors and an unreachable AppSec endpoint are configured to block. This balances streaming compatibility with fail-closed AppSec availability; create a narrowly tested route-specific exception only when a real workload requires different behavior.

The rate limit of `100` requests per second with a burst of `150`, and the `20` in-flight request ceiling, are starting values rather than measured capacity guarantees. Reassess them for uploaders, streaming applications, and high-frequency APIs. The shared HSTS policy does not enable `includeSubDomains` or preload, because the registered domain may also host unrelated sites.

### Network and Security Boundaries

The main Compose project creates the explicitly named `traefik-net`. Traefik, CrowdSec, and Authelia join it for internal communication. The later code-server stack consumes that existing network with `external: true`; it does not create a second editor network.

Only Traefik publishes LXC ports `80` and `443`. CrowdSec's Local API and AppSec listener and Authelia's HTTP listener are reachable only on `traefik-net`. No service receives the Docker socket. CrowdSec reads the Traefik JSON access log from a read-only bind mount, while both `/etc/crowdsec` and `/var/lib/crowdsec/data` are persistent.

Traefik accepts forwarded-client headers only from explicitly configured upstream proxies; this reference deployment has none. Authelia's current ForwardAuth integration still uses `trustForwardHeader: true`, but Traefik sanitizes untrusted entry-point headers first. Test this boundary after deployment.

Direct LAN requests normally retain the client address. Tailscale subnet routing uses source NAT by default, so those requests normally appear as the subnet router's LAN address (`192.168.0.103` in the reference plan). If Tailscale source NAT is deliberately disabled, the client remains in `100.64.0.0/10`, which the allowlist also permits. Do not add either permitted range to CrowdSec `clientTrustedIPs`; doing so would bypass the plugin for the traffic this design intends to inspect.

### Configuration Directory Layout

Configuration, generated state, logs, notifications, and secrets have separate mounts:

```text
/
|-- TRAEFIK/
|   |-- config/
|   |   |-- traefik.yaml             # startup configuration
|   |   `-- dynamic/                  # hot-reloaded route files
|   |-- acme/acme.json                # certificate state, mode 0600
|   |-- logs/access.log               # JSON input for CrowdSec
|   `-- secrets/                      # Cloudflare token and bouncer key
|-- CROWDSEC/
|   |-- config/acquis.d/              # file-log and AppSec acquisitions
|   `-- data/                          # persistent Local API and engine state
`-- AUTHELIA/
    |-- config/
    |   |-- configuration.yml         # application configuration
    |   `-- users_database.yml        # hashed local identities
    |-- data/                          # SQLite state and bootstrap notifier
    `-- secrets/                       # JWT, session, and storage keys
```

code-server later receives only `/TRAEFIK/config`, CrowdSec acquisition configuration, and Authelia's `configuration.yml`. It does not receive the user database, notifier, certificate state, application data, Docker socket, or any secret path.

## Before You Begin

Do not begin the LXC deployment until every item below is true:

- The [Custom Domain](<4.0 Setup custom domain.md>) chapter is complete, the Cloudflare zone is **Active**, and its restricted DNS token is available from protected storage.
- AdGuard Home returns `192.168.0.102` for a private test hostname beneath `*.<MY-DOMAIN>.com`, while a public resolver does not publish a homelab A, AAAA, or CNAME target.
- The router does not forward Internet traffic to LXC ports `80` or `443`.
- Komodo Core is reachable at `192.168.0.100:9120`, and direct **Node → Shell** and **LXC → Console** access are available.
- LXC ID `102`, address `192.168.0.102`, and host ports `80` and `443` are unused.
- The Proxmox host, LXC, workstation, and authenticator have accurate time.
- A password manager, an authenticator application, a chosen Authelia identity, and a secure way to transfer repository files to the LXC are available.

Keep the LXC console available through credential registration, TOTP enrollment, and final verification. It is the recovery path if browser authentication or routing fails.

Cloudflare is the fully documented reference provider, not a universal requirement. If another DNS provider supported by Traefik's DNS challenge is used, replace the provider name, credential variable, secret mount, and token-scope procedure with that provider's current requirements; do not paste the Cloudflare Compose unchanged.

If the LAN or domain differs from the reference plan, replace the complete addresses, subnet, and domain consistently in configuration and verification commands. A domain that does not end in `.com` must replace the complete `<MY-DOMAIN>.com` value.

## Setup LXC

Create the reverse proxy LXC by running one of the following [Docker helper script](https://community-scripts.org/scripts/docker) commands on the Proxmox node (**Node → Shell**).

```sh
# Recommended: use the guide's predefined settings
mode=generated var_unprivileged=1 var_nesting=1 var_keyctl=1 var_ctid=102 var_hostname=traefik var_cpu=2 var_ram=2048 var_disk=16 var_brg=vmbr0 var_net=192.168.0.102/24 var_gateway=192.168.0.1 var_tags=essential var_protection=yes bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/docker.sh)"

# Alternative: launch the interactive installer
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/docker.sh)"
```

Use these settings as the acceptance baseline:

| Setting | Reference value |
| --- | --- |
| Container type | Unprivileged |
| Container ID | `102` |
| Hostname | `traefik` |
| Disk size | 16 GiB |
| CPU cores | 2 |
| RAM | 2048 MiB |
| Network bridge | `vmbr0` |
| IPv4 configuration | Static: `192.168.0.102/24`; gateway: `192.168.0.1` |
| Container tag | `essential` |
| Nesting | Enabled |
| Keyctl | Enabled |
| Container protection | Enabled |

The allocation is shared by Traefik, CrowdSec, Authelia, and the intermittent code-server container. Start with these values, monitor pressure, and raise memory before enabling more AppSec rules or running a heavy editor workload. During Docker installation, decline Portainer, the Portainer Agent, and Docker TCP socket exposure. Komodo will manage this Docker host and does not require an additional management UI or an insecure TCP listener.

Use only one creation command, and review the downloaded script before execution if the upstream content has changed. The helper script must finish successfully. Then verify the LXC's settings from the UI or the Proxmox node (**Node → Shell**):

```sh
pct status 102
pct config 102
```

Confirm that the LXC is running, is unprivileged and protected, uses the intended resources, static address, and bridge, and has nesting and keyctl enabled. Resolve any mismatch before continuing.

Open the reverse proxy LXC (**LXC → Console**) and verify its address, time synchronization, and Docker installation:

```sh
ip -brief address
timedatectl status
docker version
```

The expected address is `192.168.0.102/24`, time synchronization is active, and both Docker client and server respond. Fix any failure before continuing.

## Prepare the Host

Preparation creates the exact directories, empty runtime files, generated secrets, permissions, and access log needed by the combined stack. Choose the recommended script or the manual equivalent; do not perform both. The paths converge before the canonical configuration is installed.

### Create the Configuration Layout with the Bootstrap Script (Recommended)

Review [`traefik-bootstrap.sh`](<../Application Library/Reverse Proxies/Traefik/Scripts/traefik-bootstrap.sh>) before running it as `root`. From a PowerShell prompt on a trusted workstation, with this repository as the current directory, transfer the repository copy:

```powershell
scp "Application Library/Reverse Proxies/Traefik/Scripts/traefik-bootstrap.sh" root@192.168.0.102:/root/traefik-bootstrap.sh
```

In the reverse proxy LXC (**LXC → Console**), inspect and run it:

```sh
less /root/traefik-bootstrap.sh
install -m 0750 /root/traefik-bootstrap.sh /usr/local/sbin/traefik-bootstrap.sh
/usr/local/sbin/traefik-bootstrap.sh
```

The script creates the canonical layout, empty configuration and runtime files, and three random Authelia secrets. It tightens ownership and permissions, refuses symlink targets, preserves non-empty configuration and secrets on reruns, and deliberately leaves the Cloudflare token and CrowdSec bouncer key empty. It does not create Docker networks, start containers, contact Cloudflare, or register a bouncer.

### Create the Configuration Layout Manually

Run this complete alternative in the reverse proxy LXC (**LXC → Console**). It preserves existing files and non-empty secrets on reruns.

```bash
set -Eeuo pipefail
umask 077
command -v openssl >/dev/null || { echo 'openssl is required.' >&2; exit 1; }

ensure_dir() {
  local path=$1 mode=$2 owner=$3 group=$4
  if [ -L "$path" ] || { [ -e "$path" ] && [ ! -d "$path" ]; }; then
    echo "Refusing non-directory path: $path" >&2
    exit 1
  fi
  if [ ! -d "$path" ]; then
    install -d -m "$mode" -o "$owner" -g "$group" "$path"
  fi
  chmod "$mode" "$path"
  chown "$owner:$group" "$path"
}

ensure_dir /TRAEFIK 0750 root root
ensure_dir /TRAEFIK/config 0770 1000 1000
ensure_dir /TRAEFIK/config/dynamic 0770 1000 1000
ensure_dir /TRAEFIK/acme 0700 root root
ensure_dir /TRAEFIK/logs 0750 root root
ensure_dir /TRAEFIK/secrets 0700 root root
ensure_dir /CROWDSEC 0750 root root
ensure_dir /CROWDSEC/config 0750 root root
ensure_dir /CROWDSEC/config/acquis.d 0770 1000 1000
ensure_dir /CROWDSEC/data 0750 root root
ensure_dir /AUTHELIA 0750 root root
ensure_dir /AUTHELIA/config 0770 1000 1000
ensure_dir /AUTHELIA/data 0700 1000 1000
ensure_dir /AUTHELIA/secrets 0700 1000 1000

ensure_file() {
  local path=$1 mode=$2 owner=$3 group=$4
  if [ -L "$path" ] || { [ -e "$path" ] && [ ! -f "$path" ]; }; then
    echo "Refusing non-regular file path: $path" >&2
    exit 1
  fi
  if [ ! -e "$path" ]; then
    install -m "$mode" -o "$owner" -g "$group" /dev/null "$path"
  fi
  chmod "$mode" "$path"
  chown "$owner:$group" "$path"
}

ensure_file /TRAEFIK/config/traefik.yaml 0660 1000 1000
for file in middlewares.yaml tls.yaml traefik.yaml authelia.yaml code-server.yaml \
  proxmox-ve.yaml proxmox-backup-server.yaml ups.yaml komodo.yaml \
  adguard-home.yaml gotify.yaml beszel.yaml uptime-kuma.yaml myspeed.yaml homepage.yaml; do
  ensure_file "/TRAEFIK/config/dynamic/$file" 0660 1000 1000
done
ensure_file /TRAEFIK/acme/acme.json 0600 root root
ensure_file /TRAEFIK/logs/access.log 0640 root root
ensure_file /TRAEFIK/secrets/cf_dns_api_token 0600 root root
ensure_file /TRAEFIK/secrets/.crowdsecLapiKey 0600 root root
ensure_file /CROWDSEC/config/acquis.d/traefik.yaml 0660 1000 1000
ensure_file /CROWDSEC/config/acquis.d/appsec.yaml 0660 1000 1000
ensure_file /AUTHELIA/config/configuration.yml 0660 1000 1000
ensure_file /AUTHELIA/config/users_database.yml 0660 1000 1000
ensure_file /AUTHELIA/data/notification.txt 0600 1000 1000

generate_secret() {
  local path=$1 temporary
  if [ -L "$path" ] || { [ -e "$path" ] && [ ! -f "$path" ]; }; then
    echo "Refusing non-regular secret path: $path" >&2
    exit 1
  fi
  if [ -s "$path" ]; then
    chmod 0400 "$path"
    chown 1000:1000 "$path"
    return
  fi
  temporary=$(mktemp "${path}.tmp.XXXXXX")
  openssl rand -hex 64 | tr -d '\n' > "$temporary"
  chmod 0400 "$temporary"
  chown 1000:1000 "$temporary"
  mv -f "$temporary" "$path"
}

generate_secret /AUTHELIA/secrets/jwt_secret
generate_secret /AUTHELIA/secrets/session_secret
generate_secret /AUTHELIA/secrets/storage_encryption_key
```

These commands create editable configuration as UID/GID `1000`, root-only Traefik credential and ACME files, Authelia-readable secret files, persistent application state, and the shared access log. The bouncer key correctly remains empty until CrowdSec runs.

### Install and Customize the Canonical Configuration

Both preparation paths continue here. Only the foundation route files are installed now; later service templates remain empty until their services are deployed.

From a PowerShell prompt on the trusted repository workstation, run:

```powershell
$source = "Application Library/Reverse Proxies/Traefik/Config files"

scp "$source/Traefik/traefik.yaml" root@192.168.0.102:/TRAEFIK/config/traefik.yaml

$routes = @(
  "$source/Traefik/dynamic/middlewares.yaml",
  "$source/Traefik/dynamic/tls.yaml",
  "$source/Traefik/dynamic/traefik.yaml",
  "$source/Traefik/dynamic/authelia.yaml",
  "$source/Traefik/dynamic/proxmox-ve.yaml",
  "$source/Traefik/dynamic/komodo.yaml",
  "$source/Traefik/dynamic/adguard-home.yaml"
)
scp $routes root@192.168.0.102:/TRAEFIK/config/dynamic/

scp "$source/CrowdSec/acquis.d/traefik.yaml" root@192.168.0.102:/CROWDSEC/config/acquis.d/traefik.yaml
scp "$source/CrowdSec/acquis.d/appsec.yaml" root@192.168.0.102:/CROWDSEC/config/acquis.d/appsec.yaml
scp "$source/Authelia/configuration.yml" root@192.168.0.102:/AUTHELIA/config/configuration.yml
scp "$source/Authelia/users_database.yml" root@192.168.0.102:/AUTHELIA/config/users_database.yml
```

In the reverse proxy LXC (**LXC → Console**), replace the domain and email in the transferred configuration. Set the two shell values to the real complete values first:

```bash
DOMAIN='<MY-DOMAIN>.com'
EMAIL='<EMAIL>'

sed -i \
  -e "s|<MY-DOMAIN>\.com|${DOMAIN}|g" \
  -e "s|<EMAIL>|${EMAIL}|g" \
  /TRAEFIK/config/traefik.yaml \
  /TRAEFIK/config/dynamic/*.yaml \
  /AUTHELIA/config/configuration.yml

unset DOMAIN EMAIL
```

Review the backend URLs in `/TRAEFIK/config/dynamic/` and change an address only when the earlier network plan differs. The `skipverify` transport is a temporary trust decision for the named self-signed Proxmox, PBS, and UPS backends; prefer a trusted backend certificate when available.

In the reverse proxy LXC (**LXC → Console**), generate the local user's Argon2id hash with the pinned Authelia image. Enter the password only at the hidden prompt and do not share the resulting hash unnecessarily:

```sh
docker run --rm -it authelia/authelia:4.39.20 authelia crypto hash generate argon2
nano /AUTHELIA/config/users_database.yml
```

In `users_database.yml`, replace `<USERNAME>`, `<DISPLAY-NAME>`, `<ARGON2ID-HASH>`, and `<EMAIL>`. Save only the hash, never the plaintext password.

Still in the reverse proxy LXC (**LXC → Console**), restore the intended ownership and permissions after file transfer:

```sh
chown -R 1000:1000 /TRAEFIK/config /CROWDSEC/config/acquis.d /AUTHELIA/config
find /TRAEFIK/config /CROWDSEC/config/acquis.d /AUTHELIA/config -type d -exec chmod 0770 {} +
find /TRAEFIK/config /CROWDSEC/config/acquis.d /AUTHELIA/config -type f -exec chmod 0660 {} +
```

Store the Cloudflare token without echoing it or placing it in shell history. The following reverse proxy LXC command writes a root-only temporary file and replaces the destination atomically:

```bash
read -rsp 'Cloudflare DNS API token: ' CF_TOKEN
printf '\n'
CF_TEMP=$(mktemp /TRAEFIK/secrets/.cf-token.XXXXXX)
printf '%s' "$CF_TOKEN" > "$CF_TEMP"
unset CF_TOKEN
chmod 0600 "$CF_TEMP"
chown root:root "$CF_TEMP"
mv -f "$CF_TEMP" /TRAEFIK/secrets/cf_dns_api_token
unset CF_TEMP
test -s /TRAEFIK/secrets/cf_dns_api_token && echo 'Cloudflare token file is non-empty.'
```

The token is consumed through `CF_DNS_API_TOKEN_FILE`; it is not stored in `traefik.env` or printed by the guide. The bouncer key must still be empty.

### Configure Access-Log Rotation

CrowdSec tails `/TRAEFIK/logs/access.log`, so the file must not grow without a limit. Install `logrotate` if necessary, then create `/etc/logrotate.d/traefik-access` in the reverse proxy LXC with this file content:

```text
/TRAEFIK/logs/access.log {
    daily
    rotate 14
    size 20M
    missingok
    notifempty
    compress
    delaycompress
    copytruncate
    su root root
}
```

`copytruncate` keeps Traefik and CrowdSec on the same active pathname without requiring a proxy restart, at the cost of a small possible race while copying. In the reverse proxy LXC (**LXC → Console**), validate the policy without rotating the file:

```sh
logrotate --debug /etc/logrotate.d/traefik-access
```

The debug run must report a valid policy and no permission error.

### Verify Host Preparation

If the bootstrap path was used, run its non-writing check in the reverse proxy LXC (**LXC → Console**):

```sh
/usr/local/sbin/traefik-bootstrap.sh --verify-only
```

For either path, run these checks in the reverse proxy LXC (**LXC → Console**):

```sh
test -s /TRAEFIK/secrets/cf_dns_api_token
test ! -s /TRAEFIK/secrets/.crowdsecLapiKey
test -s /AUTHELIA/secrets/jwt_secret
test -s /AUTHELIA/secrets/session_secret
test -s /AUTHELIA/secrets/storage_encryption_key
stat -c '%a %U:%G %n' \
  /TRAEFIK/acme/acme.json \
  /TRAEFIK/secrets/cf_dns_api_token \
  /TRAEFIK/secrets/.crowdsecLapiKey \
  /AUTHELIA/data/notification.txt \
  /AUTHELIA/secrets/*
grep -RInE '<(MY-DOMAIN|EMAIL|USERNAME|DISPLAY-NAME|ARGON2ID-HASH)>' \
  /TRAEFIK/config /CROWDSEC/config/acquis.d /AUTHELIA/config
```

The first five commands succeed. `acme.json`, the Cloudflare token, and bouncer-key file are `600 root:root`; the Authelia notifier is `600 1000:1000`; Authelia secrets are `400 1000:1000`. The final `grep` produces no output. A missing file, leftover placeholder, empty required secret, or unexpected permission blocks deployment.

Do not create `traefik-net` manually. The main Compose project owns it and will create it during deployment.

### Configure and Initialize the Stack

The files and Compose definition are now present, but the configurations must be checked, the one-time bouncer credential must be registered, and Traefik must consume that credential before the stack is ready.

#### Validate the Prepared Configuration

Run these commands in the reverse proxy LXC (**LXC → Console**):

```sh
docker exec crowdsec crowdsec -t
docker exec crowdsec cscli lapi status
docker exec authelia authelia config validate --config /config/configuration.yml
docker exec authelia /app/healthcheck.sh
```

Each command exits successfully. Authelia's command validates syntax and internal configuration rules; it does not prove DNS, cookies, ForwardAuth, routing, or browser login.

Still in the reverse proxy LXC (**LXC → Console**), confirm the files and mounts without reading their contents:

```sh
test -s /TRAEFIK/secrets/cf_dns_api_token
test -s /AUTHELIA/config/users_database.yml
test -s /AUTHELIA/secrets/jwt_secret
test -s /AUTHELIA/secrets/session_secret
test -s /AUTHELIA/secrets/storage_encryption_key
stat -c '%a %U:%G %s %n' /TRAEFIK/acme/acme.json /TRAEFIK/secrets/* /AUTHELIA/secrets/*
docker inspect crowdsec authelia traefik \
  --format '{{.Name}}{{range .Mounts}}{{println "  " .Source "->" .Destination}}{{end}}'
```

The mount list agrees with the Compose file, includes no Docker socket, and does not expose one service's secrets to another. Do not paste `docker inspect` output publicly; although these checks avoid values, paths and metadata may still reveal system details.

Still in the reverse proxy LXC (**LXC → Console**), confirm the expected CrowdSec content and acquisitions:

```sh
docker exec crowdsec cscli collections list
docker exec crowdsec cscli appsec-configs list
docker exec crowdsec cscli metrics show acquisition
```

The Traefik and two AppSec collections are installed, `crowdsecurity/appsec-default` is available, and acquisitions identify `/var/log/traefik/access.log` plus the AppSec listener. A new access log may have zero lines before traffic exists; a missing acquisition is a blocker.

#### Register the Traefik Bouncer with CrowdSec

First list registered bouncers in the reverse proxy LXC (**LXC → Console**):

```sh
docker exec crowdsec cscli bouncers list
```

A clean installation is expected to have no `traefik-bouncer`. If that exact name already exists, stop. CrowdSec cannot reveal its original key; locate the protected original or plan an explicit delete-and-reissue rotation. Do not create a duplicate just because the key is unavailable.

> [!WARNING]
> The next command issues a one-time credential. It writes raw output directly to a root-only temporary file and never displays the key. If the command is interrupted after CrowdSec creates the bouncer, treat the result as a deliberate rotation case instead of running it repeatedly.

Run this once in the reverse proxy LXC (**LXC → Console**):

```bash
set -Eeuo pipefail
ISSUED=$(mktemp /TRAEFIK/secrets/.issued-bouncer.XXXXXX)
FINAL=$(mktemp /TRAEFIK/secrets/.final-bouncer.XXXXXX)
trap 'rm -f -- "$ISSUED" "$FINAL"' EXIT

docker exec crowdsec cscli bouncers add traefik-bouncer -o raw > "$ISSUED"
BOUNCER_KEY=$(<"$ISSUED")
case "$BOUNCER_KEY" in
  ''|*[[:space:]]*) echo 'Invalid bouncer-key output; stop.' >&2; exit 1 ;;
esac
printf '%s' "$BOUNCER_KEY" > "$FINAL"
unset BOUNCER_KEY
chmod 0600 "$FINAL"
chown root:root "$FINAL"
install -m 0600 -o root -g root "$FINAL" /TRAEFIK/secrets/.crowdsecLapiKey.new
mv -f /TRAEFIK/secrets/.crowdsecLapiKey.new /TRAEFIK/secrets/.crowdsecLapiKey
rm -f -- "$ISSUED" "$FINAL"
trap - EXIT
```

Still in the reverse proxy LXC (**LXC → Console**), verify presence and protection without printing the value:

```sh
test -s /TRAEFIK/secrets/.crowdsecLapiKey
test "$(wc -l < /TRAEFIK/secrets/.crowdsecLapiKey)" -eq 0
stat -c '%a %U:%G %s %n' /TRAEFIK/secrets/.crowdsecLapiKey
docker exec crowdsec cscli bouncers list
```

The file is a non-empty single value with `600 root:root`, and `traefik-bouncer` appears once. The file is mounted only into Traefik; CrowdSec already stored the registered credential through its Local API.

#### Apply the Configuration

The atomic key replacement changes the host file inode, so a simple stop/start is not sufficient to guarantee that the Compose secret is remounted. Recreate only Traefik.

> [!WARNING]
> Removing the Traefik Docker container causes brief proxy downtime. Its configuration, log, secret, and ACME state are bind-mounted and remain on the LXC. Do not remove CrowdSec or Authelia, and deploy the stack immediately afterward.

In the reverse proxy LXC (**LXC → Console**), remove only the Traefik container:

```sh
docker rm -f traefik
```

Return to the `traefik` stack in Komodo and select **Deploy**. Compose recreates the missing Traefik service and leaves the healthy CrowdSec and Authelia containers in place.

For later maintenance, use this apply matrix:

| Change | Required apply action |
| --- | --- |
| `/TRAEFIK/config/dynamic/*.yaml` | Wait for file-provider hot reload; inspect Traefik logs |
| `/TRAEFIK/config/traefik.yaml` or a mounted Traefik secret | Recreate Traefik |
| CrowdSec acquisitions or startup-installed hub items | Restart CrowdSec after `crowdsec -t` succeeds |
| Authelia configuration, users, or secret references | Validate, then restart Authelia |
| New bouncer registered through LAPI | No CrowdSec restart; recreate only the consumer when its mounted key changed |

A controlled whole-stack redeploy is an alternative during a maintenance window, but it creates more interruption and is not the default response to a dynamic route edit.

Run these checks in the reverse proxy LXC (**LXC → Console**):

```sh
docker exec crowdsec cscli lapi status
docker exec crowdsec cscli bouncers inspect traefik-bouncer
```

The LAPI, Authelia, and Traefik checks succeed; the bouncer shows recent Local API activity after Traefik starts; the network contains all three containers; and both known backends respond from the LXC. Backend success does not yet prove client DNS, TLS, routing, middleware, or login.

Still in the reverse proxy LXC (**LXC → Console**), inspect only recent focused errors, never secret or ACME contents:

```sh
docker logs --since 5m crowdsec 2>&1 | grep -Ei 'error|fatal|acquis|appsec' || true
```

An authentication error, acquisition failure, empty credential, unreachable internal endpoint, parse error, or failed health check blocks TOTP enrollment.

### Enroll Two-Factor Authentication

The Authelia identity now has a password-based first factor, but the Traefik dashboard rule requires TOTP. Use a trusted client and keep **LXC → Console** access open throughout enrollment.

1. Open `https://traefik.<MY-DOMAIN>.com/dashboard/`.
2. Follow the Authelia redirect and sign in with the configured username and password.
3. Select **One-Time Password**, then **Register device**.
4. Request identity verification. This release sends a one-time code or verification message to the configured notifier.
5. In the LXC console, open only the newest message with `less +G /AUTHELIA/data/notification.txt`; do not dump the whole file into terminal history. Use the latest identity-verification value in Authelia.
6. Scan the displayed QR code with the authenticator, enter the current TOTP code, and confirm registration.
7. Confirm that the browser returns to the original `/dashboard/` route and the dashboard loads.

Treat the QR code, TOTP seed, one-time code or link, session cookie, and notification as credentials. Do not screenshot or paste them. Authelia does not present generic TOTP recovery codes in this enrollment flow; use only recovery or encrypted-export features explicitly supported by the chosen authenticator, and protect backups of Authelia's SQLite state and storage encryption key separately from the host.

The filesystem notifier is accepted only as a constrained bootstrap mechanism for this private single-node setup; [Authelia recommends it only for testing](https://www.authelia.com/configuration/notifications/file/). It is writable only by UID `1000`, is not mounted into code-server, and must never be committed.

> [!WARNING]
> Clear the bootstrap notification only after TOTP registration and a fresh TOTP login have both succeeded. Truncation removes the latest one-time message.

In the reverse proxy LXC (**LXC → Console**), clear the bootstrap notification:

```sh
install -m 0600 -o 1000 -g 1000 /dev/null /AUTHELIA/data/notification.txt
```

When a mail-capable service is available, replace the filesystem notifier with Authelia's SMTP provider, keep its password in a `_FILE` secret, validate the configuration, restart Authelia, test delivery, and then remove any retained bootstrap messages.

## Verify the Complete Setup

This is a blocking gate. Do not continue to code-server until routing, certificates, CrowdSec, AppSec, Authelia, persistence, and the private-access boundary all pass. Run each command in the stated context, keep output private, and stop on a failed expectation.

### Verify Traefik and HTTPS

In the reverse proxy LXC (**LXC → Console**), check published ports and network membership:

```sh
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker network inspect traefik-net --format '{{range $id, $container := .Containers}}{{println $container.Name}}{{end}}'
```

Only `traefik` publishes `80` and `443`. `crowdsec` and `authelia` publish no host ports, and all three appear on `traefik-net`.

On a LAN workstation, verify private and public DNS separately:

```sh
nslookup "traefik.<MY-DOMAIN>.com" 192.168.0.101
nslookup "auth.<MY-DOMAIN>.com" 192.168.0.101
nslookup "traefik.<MY-DOMAIN>.com" 1.1.1.1
```

The AdGuard queries return `192.168.0.102`. The public query must not return a homelab address or public target that routes to it. Confirm separately that the router still has no inbound `80`/`443` forward.

On the LAN workstation, check redirect and certificate behavior:

```sh
curl -I "http://traefik.<MY-DOMAIN>.com/dashboard/"
curl -fsSI "https://traefik.<MY-DOMAIN>.com/dashboard/" >/dev/null && echo 'HTTPS trust and hostname check passed.'
openssl s_client -connect "traefik.<MY-DOMAIN>.com:443" -servername "traefik.<MY-DOMAIN>.com" </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -ext subjectAltName
```

HTTP returns a permanent redirect to HTTPS. The certificate chain is trusted and its subject alternative names cover the requested hostname. Do not use `curl -k` as proof of certificate trust.

Open these exact private routes in a browser:

- `https://traefik.<MY-DOMAIN>.com/dashboard/` - the host-and-path `api@internal` router and `secured-auth` apply; insecure dashboard mode remains disabled.
- `https://auth.<MY-DOMAIN>.com` - the Authelia portal loads without an authentication loop.
- `https://komodo.<MY-DOMAIN>.com` - `secured` permits the application's own login.
- `https://adguard.<MY-DOMAIN>.com` - `secured-auth` completes Authelia and reaches AdGuard Home.

Confirm the dashboard route does not become a hostname-wide catch-all by requesting another path and expecting no dashboard page.

Test forwarded-header sanitization from the LAN workstation:

```sh
curl -sS -o /dev/null -H 'X-Forwarded-For: 203.0.113.9' \
  "https://komodo.<MY-DOMAIN>.com/header-attribution-check"
```

Immediately inspect only that marker in the reverse proxy LXC (**LXC → Console**):

```sh
python3 -c 'import json; p="/TRAEFIK/logs/access.log"; rows=open(p, encoding="utf-8").readlines(); print(next(json.loads(x)["ClientHost"] for x in reversed(rows) if "header-attribution-check" in x))'
```

The result is the real LAN source address, not `203.0.113.9`. After the VPN chapter, repeat from Tailscale: default subnet-router source NAT should show `192.168.0.103`; a deliberate no-SNAT design should show a `100.64.0.0/10` client.

Check focused Traefik logs for route, plugin, Cloudflare, and ACME errors without displaying the token or `acme.json`. If issuance fails, first diagnose token scope, authoritative nameservers, domain spelling, DNS propagation, file permissions, and time. Repeated deletion of certificate state can consume CA rate limits and is not a normal retry method.

## Choose a Middleware for Later Services

Later chapters reuse the two chains. Selecting the wrong chain can break an otherwise healthy application.

| Chain | Exact order | Choose it for |
| --- | --- | --- |
| `secured` | allowlist → CrowdSec/AppSec → headers → rate limit → in-flight limit | Native authentication, APIs, webhooks, native clients, monitoring endpoints, token integrations |
| `secured-auth` | allowlist → CrowdSec/AppSec → Authelia → headers → rate limit → in-flight limit | Compatible interactive browser routes with an explicit Authelia access rule |

Before choosing, ask:

- Does the route need an interactive browser login, or does its own authentication need to remain in control?
- Will a redirect or authentication cookie break an API, webhook, mobile app, WebSocket, upload, or streaming request?
- Does an explicit Authelia rule exist for this exact hostname and intended factor policy?
- Have both the browser and every native integration been tested? A browser success does not prove client compatibility.
- Do the `10 MiB` inspection limit and headers-only unreadable-body policy fit the workload?

Do not apply ForwardAuth to every hostname through an indiscriminate wildcard policy. The Authelia portal is a genuine `secured` exception to prevent a loop; services with their own login and machine clients are common additional exceptions.

Use the canonical [Add a service to Traefik](<../Quick action guides/Add a service to Traefik.md>) and [Protect a service with Authelia](<../Quick action guides/Protect a service with Authelia.md>) guides for later routes instead of duplicating their procedures here.

## Troubleshooting and Recovery

Use direct LXC console access, identify the failing layer, and inspect focused recent logs. Before editing, copy the affected configuration to a root-only directory outside Traefik's watched dynamic directory. Change one variable at a time and restore every temporary bypass after the root cause is fixed.

### Diagnose the Failure

Follow the request path from left to right:

1. DNS: does AdGuard Home return `192.168.0.102`, and does public DNS remain closed?
2. Traefik/TLS: do ports, health, route rule, certificate, and backend URL agree?
3. Middleware/plugin: which chain and ordered control returned the response?
4. CrowdSec/AppSec: is this a decision, bouncer authentication error, AppSec verdict, or unreachable dependency?
5. Authelia: do cookie domain, access rule, user, storage, notifier, and forwarded headers agree?
6. Backend: does the direct private URL work from the reverse proxy LXC?

Use `docker logs --since 5m <CONTAINER>` rather than restarting the whole stack blindly. The [reverse proxy and HTTPS troubleshooting guide](<../Other guides/Troubleshooting/Troubleshoot reverse proxy and HTTPS.md>) and [Docker/Komodo troubleshooting guide](<../Other guides/Troubleshooting/Troubleshoot Docker containers and Komodo deployments.md>) provide the broader runbooks.

### Recover from an Authentication Error

If `https://auth.<MY-DOMAIN>.com` works but one protected route loops or denies access, temporarily remove Authelia from only that route.

In the reverse proxy LXC (**LXC → Console**), back up the route outside the watched directory and edit it:

```sh
install -d -m 0700 /root/traefik-recovery
cp -a /TRAEFIK/config/dynamic/traefik.yaml /root/traefik-recovery/traefik.yaml.before-auth-recovery
nano /TRAEFIK/config/dynamic/traefik.yaml
```

Change only that router from `secured-auth@file` to `secured@file`. The file provider hot-reloads it. This temporarily removes Authelia but retains the private allowlist, CrowdSec/AppSec, headers, rate limit, and in-flight limit; use it only while the route remains private.

Inspect Traefik and Authelia, then correct the narrow cause: cookie domain, sanitized forwarded headers, user database, session/storage mount, notifier, or explicit access-control rule. Validate Authelia, restart it only if its configuration changed, restore `secured-auth@file`, and confirm a fresh password-plus-TOTP flow. Delete the temporary backup when it is no longer needed.

### Recover from a Traefik or Certificate Error

Do not empty or delete `/TRAEFIK/acme/acme.json` reflexively. First verify the Cloudflare token file and scope without printing it, authoritative nameservers, domain and email, DNS propagation, LXC time, `600` permissions, Traefik startup configuration, and recent ACME errors.

Before any deliberate certificate-state regeneration decision, stop Traefik and protect a copy in a root-only recovery directory. Account for Let's Encrypt issuance limits and document why regeneration is necessary. Recreate Traefik only after the static cause is fixed; never enable the insecure dashboard or publish internal ports as a certificate workaround.

### Recover from a CrowdSec or AppSec Block

Distinguish four failure types:

- A specific decision: inspect it and delete only the confirmed false positive.
- Bouncer authentication: confirm the registered name, protected key file, mount, and recent bouncer activity; rotate deliberately if the original key is lost.
- AppSec unreachable or server error: this design fails closed, so repair CrowdSec health, `traefik-net`, acquisition, or the internal endpoint.
- An unreadable streaming body: this design forwards headers to AppSec and leaves that body untouched; test a route-specific policy before changing the global chain.

Do not disable CrowdSec globally, add permitted networks to `clientTrustedIPs`, expose ports `8080` or `7422`, remove authentication from unrelated routes, or publish the proxy to the Internet. Finish by confirming that temporary route changes are reverted, all three health checks pass, the test route uses its intended chain, and public exposure remains closed.
