# Checklist & What's Next

That's it! You officially built your core homelab infrastructure. **Congratulations!** 🎉

Before moving on, let's verify the setup to ensure every service is running as intended.

## Checklist

In this checklist, we will verify each service is working as expected. Go through the items below to confirm that all services and configurations are working properly.

### Proxmox VE & Komodo

- [ ] Go to [Proxmox VE](<1. Setup Proxmox VE.md>) (try `https://proxmox.<MY-DOMAIN>.com` and `https://<IP>:8006/` as well), log in with the admin user. Review the Datacenter and Node status and resources in the summary windows.
- [ ] Verify that all created **LXC containers** are in a **running** state, showing normal resource usage (CPU/RAM), valid and correct IP addresses.
- [ ] Navigate through the **Datacenter** and **Node** menu tabs (System, Firewall, Permissions, Storage, etc.) to confirm that all settings, status indicators, and configured values are correct.
- [ ] Perform a planned **Host Reboot** from Proxmox VE to confirm that all LXCs and Docker containers start automatically on boot in the proper order without requiring manual intervention.
- [ ] Go to [Komodo](<2. Setup Komodo.md>) (try `https://komodo.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), log in with your admin account, and verify that the dashboard loads properly with no active alerts or connection errors.
- [ ] Go to **Komodo → Servers** and verify every Periphery server was added and reports **OK**.
- [ ] Go to **Komodo → Containers** and confirm that all expected containers display a **healthy/running** status across your connected servers.
- [ ] Go to **Komodo → Stacks** and verify that all deployed stacks show a **healthy/running** status and that their compose configurations are up-to-date.

### Networking, DNS & Remote Access

- [ ] Go to [AdGuard Home](<3. Setup DNS Server.md>) (try `https://adguard.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), log in with the admin user. Review the dashboard and verify that the DNS server is running and filtering ads and trackers. Verify router uses AdGuard's IP as **Primary DNS** and network is working. Other devices on the network can access the internet, don't have speed issues and private hostnames resolve to the correct IP addresses.
- [ ] Check your **router configuration** to ensure homelab management interfaces or backend ports are **NOT** exposed via port forwarding to the public internet.
- [ ] The [custom domain](<4.0 Setup custom domain.md>) is active at your DNS provider (e.g. Cloudflare) and the API token has the correct permissions for DNS-01 SSL certificate validation.
- [ ] Go to [Traefik](<4.1 Setup Reverse Proxy.md>) (try `https://traefik.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), log in to the dashboard (Authelia should trigger and require **2FA login** before granting access) and verify that all HTTP/HTTPS routers, services, and middlewares report **success**. Confirm that all configured homelab services load over HTTPS with a valid SSL certificate (no browser security warnings) and HTTP-to-HTTPS redirection works as intended.
- [ ] Verify that every service configured with the **Authelia** middleware properly prompts for single-factor or 2FA authentication, and that successful login grants access to the application.
- [ ] Go to **Komodo → Terminals** and add a New Terminal. (Type: `Container`, Server: `102-traefik`, Container: `traefik_crowdsec`) and check **CrowdSec** by running `cscli bouncers list` and `cscli metrics` to confirm that the LAPI is running, your Traefik bouncer is registered and active, and log streams (Traefik/Authelia) are being parsed without errors.
- [ ] Go to [Code-Server](<4.2 Setup Code-Server for config files.md>) (try `https://code.traefik.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), verify that Authelia requires a login and confirm the VS Code interface loads. Check that your configuration directories and files are visible, accessible, and can be edited and saved without permission errors.
- [ ] Go to [Tailscale](<5. Setup VPN.md>) [admin console](https://console.tailscale.com/admin/machines) and verify your subnet router is connected and approved. Then connect your client device (e.g. phone with Tailscale app) to an external network (e.g. mobile data) and confirm that you have full access to all services as if you were on your home network. Then disconnect from tailnet and verify you can't access any services.

### Notifications & Monitoring

- [ ] Go to [Gotify](<6.0 Setup Notification server.md>) (try `https://gotify.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), log in with the admin user, and confirm all connected applications are active, and can see notification history. Then choose an app that has Gotify integration and send a test notification to your phone.
- [ ] Go to [Beszel](<6.1 Setup Monitoring tools.md#setup-beszel>) (try `https://beszel.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), log in, and confirm the Hub is healthy and all deployed systems show their **Beszel Agent** online with live CPU, RAM, disk, and network metrics updating.
- [ ] Go to [Uptime Kuma](<6.1 Setup Monitoring tools.md#setup-uptime-kuma>) (try `https://status.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), verify that all configured monitors report **Up** (green), and perform a test notification through the configured Gotify notification provider.
- [ ] Go to [MySpeed](<6.1 Setup Monitoring tools.md#setup-myspeed>) (try `https://myspeed.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well), run an on-demand speed test, and confirm that automated scheduled tests and chart histories are recording properly.
- [ ] Go to [Homepage](<6.1 Setup Monitoring tools.md#setup-homepage>) (try `https://homepage.<MY-DOMAIN>.com` and `https://<IP>:<PORT>/` as well) and confirm that all service bookmarks, status badges, and integration widgets (if configured) load live data and open their target HTTPS URLs correctly.

### Backups & Power Protection

- [ ] Go to [Proxmox Backup Server (PBS)](<7. Setup Proxmox Backup Server.md>) (try `https://pbs.<MY-DOMAIN>.com` and `https://<IP>:8007/` as well), log in with the admin user, and verify that all datastores report **OK** with healthy disk storage. Navigate through the menu tabs to confirm that all settings, status indicators, and configured values are correct.
- [ ] In **PBS → Datastore**, confirm that Prune, Garbage Collection (GC), Sync and Verify job schedules are configured and do not overlap with scheduled backup windows.
- [ ] Go to **Proxmox VE → Datacenter → Backup**, run a manual backup of a test LXC container to PBS, and verify that the backup task finishes with a status of **OK** and appears in the PBS server too.
- [ ] Perform a test restore from PBS into Proxmox VE using an unused test ID (e.g. `999`) with network disconnected to verify backup integrity without conflicting with live production services.
- [ ] *(Optional)* Go to [UPS Software](<8. Setup UPS Software.md>) (NUT / PowerMaster+), verify communication with your UPS hardware, confirm battery/load metrics report accurately, and perform a test notification.
- [ ] *(Optional)* Simulate a power outage event by unplugging the UPS from mains power to confirm that homelab stays online and the shutdown script triggers at low battery, safely stops all LXCs/VMs, and powers off the Proxmox host without data corruption.

## What's Next

Completing `Initial Setup` means the core environment is ready for normal operation and carefully chosen applications. It doesn't mean every optional integration or advanced feature should be enabled immediately, add complexity only when it solves a real need.

### Take Time to Explore

Your first step after completing the `Initial Setup` is simply getting used to your new homelab. Take some time to explore and get familiar with it. Don't rush into advanced topics until you feel completely comfortable with the basics.
