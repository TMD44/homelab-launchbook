# DNS Server

With Proxmox VE and Komodo ready, the next step is to set up AdGuard Home as the DNS server for your home network. It provides network-wide filtering and local name resolution now, then becomes the DNS foundation for the custom-domain and reverse-proxy chapters that follow.

## About AdGuard Home

[AdGuard Home](https://adguard.com/en/adguard-home/overview.html) is a free, open-source DNS filtering service. It can block ads, trackers, and malicious domains for every device that uses it, and it provides query logs, filtering rules, and local DNS rewrites through a web interface.

## Before You Begin

- Complete and verify the preceding Proxmox and Komodo setup chapters.
- This guide uses LXC ID `101`, hostname `adguard-dns1`, address `192.168.0.101`, gateway `192.168.0.1`, and bridge `vmbr0`. Confirm that the ID and address are unused, reserve the address or keep it outside the DHCP pool, and adapt every later occurrence consistently if your network differs.
- Have access to the router administration interface and the Proxmox or LXC console. Record the router's current LAN/DHCP DNS settings before changing them so that you have a known rollback value.

## Setup LXC

Create the AdGuard Home LXC by running one of the following [Docker helper script](https://community-scripts.org/scripts/docker) commands on the Proxmox node (**Node → Shell**).

```sh
# Recommended: use the guide's predefined settings
mode=generated var_os='debian' var_unprivileged=1 var_nesting=1 var_keyctl=1 var_ctid=101 var_hostname=adguard-dns1 var_cpu=1 var_ram=256 var_disk=8 var_brg=vmbr0 var_net=192.168.0.101/24 var_gateway=192.168.0.1 var_tags=essential var_protection=yes bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/docker.sh)"

# Alternative: launch the interactive installer
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/docker.sh)"
```

Use these settings as the acceptance baseline:

| Setting | Reference value |
| --- | --- |
| Container type | Unprivileged |
| Operating system | Debian 13 |
| Container ID | `101` |
| Hostname | `adguard-dns1` |
| Disk size | 8 GiB |
| CPU cores | 1 |
| RAM | 256 MiB |
| Network bridge | `vmbr0` |
| IPv4 configuration | Static: `192.168.0.101/24`; gateway: `192.168.0.1` |
| Container tag | `essential` |
| Nesting | Enabled |
| Keyctl | Enabled |
| Container protection | Enabled |
| Start at boot | Enabled by the helper |

During Docker installation, decline Portainer, the Portainer Agent, and Docker TCP socket exposure. Komodo will manage this Docker host and does not require an additional management UI or an insecure TCP listener.

The helper script must finish successfully. Then verify the LXC's settings from the UI or the Proxmox node (**Node → Shell**):

```sh
pct status 101
pct config 101
```

Confirm that the LXC is running, starts at boot, is unprivileged and protected, uses the intended static address and bridge, and has nesting and keyctl enabled. Resolve any mismatch before continuing.

Open the AdGuard Home LXC (**LXC → Console**) and verify its address, time synchronization, and Docker installation:

```sh
ip -brief address
timedatectl status
docker version
```

The intended static address must be present, the clock must be synchronized, and `docker version` must show both client and server information.

## Setup Komodo Periphery

Connect the Docker LXC to Komodo so that the stack can be deployed and monitored from Komodo Core.

### Create Onboarding Key

Go to **Komodo → Settings → Onboarding → Create New Onboarding Key**.

- **Name:** `101-adguard-dns1`
- **Expiry:** `1 day`
- Leave **Privileged** disabled, make sure **Enabled** is selected, create the key, and copy it. Privileged onboarding is unnecessary for a new server and would allow the key to update public keys on existing servers.

### Install Komodo Periphery

On the LXC (**LXC → Console**), run the setup script below:

```sh
curl -sSL https://raw.githubusercontent.com/moghtech/komodo/main/scripts/setup-periphery.py \
  | python3 - \
  --core-address="http://192.168.0.100:9120" \
  --connect-as="101-adguard-dns1" \
  --onboarding-key="<ONBOARDING_KEY>"
```

Enable Periphery at boot and verify its state:

```sh
systemctl enable periphery
systemctl is-enabled periphery
systemctl is-active periphery

systemctl status periphery
```

The last two commands must report `enabled` and `active`. Return to **Komodo → Servers** and verify that the DNS server LXC is listed with an **OK** connection status. After the connection succeeds, disable or delete the onboarding key because it is no longer needed. See the [Komodo server connection documentation](https://komo.do/docs/setup/connect-servers) for the current script behavior and troubleshooting steps.

## Setup AdGuard Home

### Create Docker Stack

Go to **Komodo → Stacks → New Stack**.

- **Stack Name:** `adguard-dns1`
- **Server:** `101-adguard-dns1`
- **Choose Mode:** `UI Defined`
- **Compose File:** paste the contents of [`adguardhome-compose.yaml`](../TODO.md)
- **Environment:** paste the contents of [`adguardhome.env`](../TODO.md)
- **Poll for Updates:** enabled
- Leave **Auto Update** and **Full Stack Auto Update** at their defaults unless you have deliberately chosen automatic deployment of image updates.
- Optionally add `https://adguard.<MY-DOMAIN>.com` under **Links** only if that domain is already planned. Otherwise, leave it blank and add the link after the custom-domain and reverse-proxy chapters.

Create and deploy the stack. During first-run setup, the health check accepts the setup wizard on port `3000`; after the wizard, it requires the web interface on port `80` and DNS listeners on TCP and UDP port `53`. Confirm that the container reports healthy before continuing.

### Application Configuration

From a trusted device on the home LAN, open `http://192.168.0.101:3000`.

1. On **Admin Web Interface**, leave **Listen interface** set to **All interfaces** and set **Port** to `80`.
2. Under **DNS server**, leave **Listen interface** set to **All interfaces** and **Port** set to `53`.
3. On **Authentication**, create an administrator username and a strong, unique password, then complete the wizard.
4. Sign in at `http://192.168.0.101`, go to **Settings → DNS settings**, select **Test upstreams**, and save only after the configured upstream servers respond successfully.
5. Leave the router's DNS settings unchanged until [basic DNS resolution](#verify-basic-dns-resolution) succeeds, then follow [Configure Router DNS Settings](#configure-router-dns-settings).

Keep ports `80` and `3000` limited to the trusted LAN; do not forward them from the internet. Direct HTTP access is the recovery path until the later reverse-proxy chapter provides private HTTPS access.

### Verify Basic DNS Resolution

Before changing the router, query AdGuard Home directly from a LAN workstation:

```sh
nslookup example.com 192.168.0.101
```

The command must return an address for `example.com`, the request must appear in **Query Log**, and the container must remain healthy. Fix basic resolution or health failures before making AdGuard Home the network DNS service.

### Configure Router DNS Settings

Only after the direct query succeeds, open the router's Internet or DHCP settings and set `192.168.0.101` as the primary DNS server. Do not configure a public resolver as a secondary DNS server because this can allow some clients to bypass AdGuard Home.

Renew the DHCP lease or reconnect one LAN workstation, then query without specifying a server:

```sh
nslookup example.com
```

Confirm that the response identifies `192.168.0.101` as the DNS server and that the request appears in AdGuard Home's **Query Log**. If client resolution fails, immediately restore the router's previously recorded DNS settings, renew the client lease, and troubleshoot through the direct LXC address before trying again.

### Continue to the Custom Domain Setup

The wildcard rewrite is conditional on having a chosen homelab domain. If you already control that domain, you may create and verify the rewrite now by following [Create the Local Wildcard DNS Rewrite](../TODO.md), then return here. Otherwise, skip the rewrite for now; the next [Custom Domain](../TODO.md) chapter registers or connects the domain before creating and verifying the same mapping.

## Maintenance and Recovery

- **Back up:** Protect both `/ADGUARDHOME/conf` and `/ADGUARDHOME/work`. Use a Proxmox guest backup or stop the stack before taking a file-level copy so that the two bind-mounted directories are captured consistently.
- **Update:** Read the [AdGuard Home release notes](https://github.com/AdguardTeam/AdGuardHome/releases), take a backup, change only `VERSION` in the stack environment, and redeploy through Komodo. Repeat the container-health, direct-DNS, client-DNS, and conditional wildcard checks before considering the update complete.
- **Roll back or restore:** Check the release notes for configuration migrations before reverting an image tag. If the older image cannot read the updated configuration safely, stop the stack and restore the matching copies of both bind-mounted directories before redeploying the previous version.
- **Decommission:** First move router clients to a working replacement resolver and verify them. Then remove dependent links, rewrites, or proxy routes before deleting the stack, its data, or the LXC. Never remove the active DNS service first.

The [official AdGuard Home Docker documentation](https://github.com/AdguardTeam/AdGuardHome/wiki/Docker) describes the image, persistent directories, ports, and container update behavior.
