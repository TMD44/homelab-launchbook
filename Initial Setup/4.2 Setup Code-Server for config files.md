# Set Up code-server for Configuration Files

[code-server](https://coder.com/docs/code-server) provides a browser-based Visual Studio Code environment. Here, it offers a more comfortable way to navigate, search, and edit the Traefik, CrowdSec, and Authelia configuration created in the previous chapter, without relying on Nano or Vim for every routine change.

code-server runs as a separate Docker container inside the existing reverse proxy LXC because the files it needs are already there. A separate LXC would add another system to maintain and require a secure file-sharing layer. This design mounts the Traefik configuration directory, CrowdSec acquisition directory, and Authelia configuration file; secrets, certificate state, application data, the Docker socket, and the rest of the LXC filesystem remain outside those mounts.

## About code-server

[code-server](https://github.com/coder/code-server) is a free, open-source project that is actively maintained and makes the Visual Studio Code experience available through a web browser. It provides familiar editing, search, an integrated terminal, built-in Git support, and extensions while running the actual workload on a Linux server.

This guide uses the [LinuxServer.io code-server image](https://docs.linuxserver.io/images/docker-code-server/) because it packages the application for a persistent Docker deployment and supports explicit numeric user and group IDs. A browser editor is convenient, but it is not a security boundary by itself: its useful capabilities are limited to the resources deliberately granted to its process.

## How code-server Is Secured

An editor with an integrated terminal and extension support can read, modify, or execute within every resource available to its process. Treat access to this code-server instance as administrative access to its mounted configuration scope.

### Limit What code-server Can Access

The canonical [`traefik-code-server-compose.yaml`](../TODO.md) deliberately uses directory-oriented mounts:

- `/TRAEFIK/config` is mounted read-write at `/workspace/traefik`.
- `/CROWDSEC/config/acquis.d` is mounted read-write at `/workspace/crowdsec/acquis.d`.
- `/AUTHELIA/config/configuration.yml` is mounted read-write at `/workspace/authelia/configuration.yml`.
- `/CODE-SERVER/config` is mounted read-write at `/config` for editor settings, extensions, and other code-server state.

This is a broader boundary than an individual-file allowlist. code-server can read and modify every file in the two mounted configuration directories, including files added there later, and can modify the mounted Authelia configuration file. All four short-syntax mounts are read-write because no `:ro` mode is declared. A read-only mount would prevent modification but not disclosure; it would not make a sensitive source safe to expose.

Secrets, `acme.json`, the Authelia user database and notification file, CrowdSec state, application data, logs, the Docker socket, and the LXC root filesystem remain outside the mounts. Do not broaden the source paths into their parent application directories merely for convenience. The sources must already exist with the types expected by Compose, especially the single Authelia file; short-syntax bind mounts can otherwise create a missing source as a directory. Verify the effective source, destination, and read/write mode after deployment. The [Docker bind-mount documentation](https://docs.docker.com/engine/storage/bind-mounts/) explains these behaviors.

The integrated terminal and every installed extension receive the same filesystem permissions as the editor. Run only trusted commands and install only extensions whose publisher, permissions, behavior, and need you have reviewed.

### Protect Access to the Editor

code-server uses the same non-root numeric identity as the prepared reverse-proxy configuration: `1000:1000`, set through `PUID` and `PGID`, with `no-new-privileges`. It has no Docker-socket mount and publishes no host port. Its separate Compose project joins only the existing external `traefik-net` created by the main reverse-proxy stack, and Traefik reaches the internal backend at `http://traefik_code_server:8443`.

This guide deliberately uses **Authelia as the single authentication layer**. The Compose file omits `PASSWORD` and `HASHED_PASSWORD`, so code-server's native login is disabled; it also omits `PROXY_DOMAIN` because the built-in port-proxy feature is not used. The private route must use `secured-auth` and an explicit Authelia `two_factor` rule. Traefik terminates browser-facing HTTPS, while the AdGuard Home wildcard and private-client allowlist keep the hostname on the approved LAN and Tailscale paths.

This boundary depends on all of those controls. Publishing port `8443`, changing the route to `secured`, weakening the Authelia rule, or allowing an untrusted Docker container onto `traefik-net` could provide a path around the intended login. Native code-server authentication is not a fallback for such a change; stop and restore the canonical design instead.

### Run It Only When Needed

code-server is an intermittent administration tool:

1. Start only the separate code-server stack in Komodo when configuration work is planned.
2. Authenticate through `https://code.<MY-DOMAIN>.com`.
3. Edit and review the required file.
4. Run the relevant Traefik, Authelia, or CrowdSec validation and apply the smallest required reload or restart.
5. If local Git history has been deliberately initialized inside a persistent mounted directory, commit the validated change there.
6. Stop the code-server stack and confirm that its Docker container is no longer running.

Stopping the editor when unused reduces its attack surface and resource use, but does not replace mount scoping, authentication, updates, or backups. Stop only the code-server stack, not the Traefik, CrowdSec, and Authelia stack. The `/CODE-SERVER/config` bind mount preserves editor settings and extensions. Workspace content persists through its separate host bind mounts; `/workspace` itself is only the container-side grouping and is not a persistent Git repository.

The Compose project retains `restart: unless-stopped`. An explicit stop remains in effect across a Docker daemon restart. A Komodo redeploy or image update deliberately recreates and starts the container, so repeat the acceptance checks and stop it again after either operation. These expectations follow Docker's [restart-policy behavior](https://docs.docker.com/engine/containers/start-containers-automatically/).

## Set Up code-server

The following steps verify the editor's approved configuration access, deploy it as a separate Komodo stack, connect it to the existing private reverse-proxy network, and make it available through the protected route.

### Grant Limited Configuration Access

Complete [Set Up the Reverse Proxy](<4.1 Setup Reverse Proxy.md>) first. Its bootstrap workflow creates the mounted configuration sources for the same `1000:1000` identity used by code-server. No second UID/GID, file-by-file ACL, or separate code-server environment file is part of this design.

The permission and mount contract is:

| Host source | Container destination | Access | Scope and consumer |
| --- | --- | --- | --- |
| `/CODE-SERVER/config` | `/config` | Read-write | Persistent code-server settings and extensions. |
| `/TRAEFIK/config` | `/workspace/traefik` | Read-write | Entire Traefik startup and dynamic configuration directory; Traefik also consumes it. |
| `/CROWDSEC/config/acquis.d` | `/workspace/crowdsec/acquis.d` | Read-write | Entire CrowdSec acquisition configuration directory; CrowdSec also consumes it. |
| `/AUTHELIA/config/configuration.yml` | `/workspace/authelia/configuration.yml` | Read-write | Authelia's main configuration and access policy. |

This does not create a nine-file writable/five-file read-only allowlist. The two mounted directories are writable as directories, so the editor can create, rename, and delete files within them. That capability is intentional and supports normal editor save behavior, but it also means access to code-server is administrative access to the whole mounted configuration scope.

Keep direct **LXC → Console** access available. Before deployment, verify the source types and the ownership established by the reverse-proxy bootstrap:

```sh
test -d /TRAEFIK/config
test -d /CROWDSEC/config/acquis.d
test -f /AUTHELIA/config/configuration.yml
test ! -L /TRAEFIK/config
test ! -L /CROWDSEC/config/acquis.d
test ! -L /AUTHELIA/config/configuration.yml
stat -c '%F %a %u:%g %n' \
  /TRAEFIK/config \
  /CROWDSEC/config/acquis.d \
  /AUTHELIA/config/configuration.yml
docker exec authelia authelia config validate --config /config/configuration.yml
docker exec crowdsec cscli version >/dev/null
docker exec traefik traefik healthcheck --ping
```

The first three sources must have the expected directory/file types and remain owned by `1000:1000`; the application checks must pass. `/CODE-SERVER/config` is the one state directory Compose may create during first deployment. Do not compensate for a failure by running code-server as root, changing it to another undocumented identity, or mounting the application parent directories that contain secrets and state.

### Create Docker Stack

Immediately before deployment, verify that the main reverse-proxy services are healthy and that their Compose project owns `traefik-net`. Run in the reverse proxy LXC (**LXC → Console**):

```sh
docker network inspect traefik-net --format 'network={{.Name}} driver={{.Driver}}'
docker inspect crowdsec authelia traefik \
  --format '{{.Name}} running={{.State.Running}} health={{if .State.Health}}{{.State.Health.Status}}{{else}}not-configured{{end}}'
```

The network must be named `traefik-net`, and all three containers must be running and healthy before code-server is deployed.

In **Komodo → Stacks → New Stack**, enter:

- **Stack Name:** `code-server`
- **Server:** `102-traefik`
- **Choose Mode:** `UI Defined`
- **Compose File:** paste [`traefik-code-server-compose.yaml`](../TODO.md)
- **Poll for Updates:** enabled
- Leave **Auto Update** and **Full Stack Auto Update** at their defaults. Enable automatic deployment only after an update has passed the same validation and rollback checks used here.
- **Links:** `https://code.<MY-DOMAIN>.com`

Do not add a Komodo **Environment** value: the current Compose file contains its image tag, `1000:1000` identity, timezone, and workspace path directly and has no interpolation inputs. The `4.130.0` application tag limits unplanned version drift, although only an image digest would make the entire image immutable.

Create and deploy the stack. Keep it running until all route and acceptance checks are complete. Komodo should report `traefik_code_server` as running and then healthy after the start period. An unhealthy container, missing source error, permission error, unexpected published port, or missing external network is a blocking result.

### Configure HTTPS Access with Traefik

The private AdGuard Home wildcard already resolves `code.<MY-DOMAIN>.com` to Traefik. This step adds the protected router and internal backend mapping without publishing code-server's port or creating a public DNS record.

#### Add the Authelia Access Rule

Authelia's final default policy is `deny`, so the code-server hostname requires an explicit allow rule. Because the editor has terminal and configuration-write access, its policy must remain `two_factor`.

The authoritative [`configuration.yml`](../TODO.md) installed in the previous chapter already places `code.<MY-DOMAIN>.com` in the `two_factor` domain list after the Authelia portal's required `bypass` rule. Keep direct **LXC → Console** access available and confirm the entry:

```sh
grep -n -A 12 '^access_control:' /AUTHELIA/config/configuration.yml
```

The relevant domain entry must be:

```yaml
        - code.<MY-DOMAIN>.com
```

If it is absent, add that one line to the existing `two_factor` domain list. Do not create a duplicate rule, change the policy to `one_factor` or `bypass`, or add a public-access exception. After any console edit, restore the canonical owner and mode in the reverse proxy LXC (**LXC → Console**):

```sh
chown 1000:1000 /AUTHELIA/config/configuration.yml
chmod 0660 /AUTHELIA/config/configuration.yml
```

Validate the complete configuration in the reverse proxy LXC (**LXC → Console**):

```sh
docker exec authelia authelia config validate --config /config/configuration.yml
```

If you changed the rule, restart only Authelia and inspect its focused status:

```sh
docker restart authelia
docker inspect authelia --format 'status={{.State.Status}} health={{.State.Health.Status}}'
docker logs --since 2m authelia
```

Validation must succeed, Authelia must return to `healthy`, and the recent log must contain no configuration or access-control error before continuing.

#### Add the Traefik Route

Open the canonical [`code-server.yaml`](../TODO.md) in the reverse proxy LXC (**LXC → Console**) and replace `<MY-DOMAIN>`:

```sh
nano /TRAEFIK/config/dynamic/code-server.yaml
```

The complete file content is:

```yaml
# Later-service template: install only when code-server is deployed.
http:
  routers:
    code-server:
      entryPoints:
        - websecure
      rule: Host(`code.<MY-DOMAIN>.com`)
      middlewares:
        - secured-auth@file
      service: code-server

  services:
    code-server:
      loadBalancer:
        passHostHeader: true
        servers:
          - url: http://traefik_code_server:8443
```

After saving, preserve the route's canonical owner and mode in the reverse proxy LXC (**LXC → Console**):

```sh
chown 1000:1000 /TRAEFIK/config/dynamic/code-server.yaml
chmod 0660 /TRAEFIK/config/dynamic/code-server.yaml
```

The shared `websecure` entry point supplies TLS, so this file does not duplicate a certificate resolver. Traefik terminates HTTPS before forwarding internal HTTP over the isolated `traefik-net` network. No obsolete WebSocket headers or host port are required.

Verify the shared network, Traefik health, and focused reload log in the reverse proxy LXC (**LXC → Console**):

```sh
docker network inspect traefik-net \
  --format '{{range .Containers}}{{println .Name}}{{end}}' |
  sort
docker exec traefik traefik healthcheck --ping
docker logs --since 2m traefik
```

Both `traefik` and `traefik_code_server` must appear on the network, Traefik's health check must pass, and the log must contain no router, middleware, service, backend, or file-provider error. Keep code-server running for the end-to-end checks below.

### Application Configuration

The protected editor is now reachable. Configure cautious save behavior and understand where optional local history can persist before making real service changes. The workflow follows code-server's [configuration and extension guidance](https://coder.com/docs/code-server/FAQ) and the [VS Code editing basics](https://code.visualstudio.com/docs/editing/codebasics); no additional application setting is mandatory.

#### Configure the Editor

Open `https://code.<MY-DOMAIN>.com` from a trusted LAN or Tailscale client and complete the Authelia password and TOTP prompts. Confirm that the Explorer opens `/workspace` and shows `traefik`, `crowdsec`, and `authelia`. Those entries are the actual writable bind mounts described earlier; they are not a narrower file allowlist and do not expose the code-server home directory or the rest of the LXC filesystem.

Open **Manage → Settings**, search for `files.autoSave`, and confirm **Files: Auto Save** is `off`. Explicit manual saves are deliberate for live configuration: a partial Traefik file can trigger a failed file-provider reload, while invalid Authelia or CrowdSec configuration can prevent a later restart. `off` is the normal default, so confirm it rather than changing unrelated settings.

Theme and menu layout are personal preferences:

- Choose **Manage → Themes → Color Theme → Dark+** only if you prefer it.
- Use **View → Appearance** or search Settings for `window.menuBarVisibility` if you want to toggle or compact the menu bar.

Keep these user-level preferences under persistent `/CODE-SERVER/config`. Do not store them in a mounted service configuration directory, disable Workspace Trust, or enable automatic formatting, saving, fixing, or other actions that can rewrite live YAML without review.

#### Initialize Local Git History

The Compose design does not provide one persistent Git repository around all three workspace entries. `/workspace` is a container-side parent, so a `.git` directory created there can disappear when the container is recreated. The single Authelia file mount also cannot persist repository metadata beside itself. Do not initialize Git at `/workspace` or claim that one repository protects every mounted configuration source.

If local rollback history is useful, initialize it separately inside a mounted directory after reviewing its complete contents. The Traefik directory is the clearest baseline because `/workspace/traefik` persists at `/TRAEFIK/config` and contains only the Traefik configuration tree established in the previous chapter. First verify that the running image provides Git, then run in the integrated code-server terminal:

```sh
cd /workspace/traefik
git --version
git init --initial-branch=main
git config --local user.name 'Homelab Configuration'
git config --local user.email 'homelab-config@localhost'
```

The identity is repository-local commit metadata, not a login. Use another descriptive local value if preferred, but do not change the container's global Git configuration. Before staging, create a deny-by-default policy for the current Traefik configuration layout:

```sh
nano /workspace/traefik/.gitignore
```

Enter this file content:

```gitignore
*
!/.gitignore
!/traefik.yaml
!/dynamic/
!/dynamic/*.yaml
```

This policy tracks the current Traefik YAML configuration and ignores future files until they are deliberately admitted. Secrets, certificate state, logs, Authelia data, CrowdSec state, code-server settings, extensions, and backup copies remain outside this Git worktree. Recheck the policy whenever the Traefik layout changes.

Verify the policy and inspect the candidate names without printing file contents:

```sh
cd /workspace/traefik
git check-ignore --no-index -v example.secret
git status --short --untracked-files=all
```

`git check-ignore` must identify the deny rule for the example name. Review every name from `git status`; it should contain only `.gitignore`, `traefik.yaml`, and the intended YAML files under `dynamic`.

Stage only those explicit paths:

```sh
git add -- \
  .gitignore \
  traefik.yaml \
  dynamic/*.yaml
git diff --cached --name-only
git diff --cached --check
git diff --cached --stat
```

Confirm that the staged names match the reviewed Traefik configuration set, then review the staged changes in code-server's built-in Source Control view. Do not copy configuration diffs into shared logs or messages. Create the baseline only after that review:

```sh
git commit -m 'Initial configuration'
git status --short
git log --oneline --decorate -1
git remote -v
```

`git status` and `git remote -v` must produce no output. This is local rollback history for `/TRAEFIK/config`, not a backup and not history for the other mounts; never push it to a public remote. Ensure the later LXC and Proxmox Backup Server backup policy protects `/TRAEFIK/config`, including its `.git` directory.

For a later change, review the diff, validate the affected application, stage only the named file, and use a meaningful commit:

```sh
git diff -- dynamic/gotify.yaml
git add -- dynamic/gotify.yaml
git commit -m 'Describe the validated Gotify route change'
```

To restore one known-good file, first record the current diff, then restore that exact path:

```sh
git diff -- dynamic/gotify.yaml
git restore --source=HEAD -- dynamic/gotify.yaml
```

Validate the restored YAML before reloading or restarting its consumer. Git history cannot replace an off-LXC backup, and a restore must not be used to conceal an unexplained configuration failure.

#### Install Optional Extensions

No extension is required for this baseline. code-server's editor, integrated terminal, and built-in Source Control interface are sufficient to edit and review the mounted files and to use Git where a persistent directory-local repository was deliberately initialized.

[GitLens](https://open-vsx.org/extension/eamodio/gitlens) is one optional example available through Open VSX, the extension registry used by code-server rather than Microsoft's proprietary Visual Studio Marketplace. It can add history and blame views, but it is not a security control and is not required for local Git.

Before installing any extension, verify its current publisher, license and feature tier, compatibility with the installed code-server/VS Code version, requested trust, accounts, network behavior, telemetry, update policy, and actual need. Extensions execute inside the editor's permission boundary and may add code or paid features. Do not install a bundle automatically or assume a GitKraken account is required for the baseline. Deliberately installed extensions persist under `/CODE-SERVER/config` and must be reviewed again during updates.

### Verify code-server

code-server is not ready until its container, private route, authentication boundary, filesystem permissions, workspace persistence, and on-demand lifecycle all behave as designed. If optional directory-local Git history was configured, verify that too. Keep direct **LXC → Console** access available throughout. Every failure below blocks completion.

#### Verify Deployment and Protected Access

Komodo must show the code-server stack as running and `traefik_code_server` as healthy. In the reverse proxy LXC (**LXC → Console**), inspect the effective state:

```sh
docker inspect traefik_code_server \
  --format 'status={{.State.Status}} health={{.State.Health.Status}}'
docker exec traefik_code_server \
  curl -fsS http://127.0.0.1:8443/healthz
docker logs --since 5m traefik_code_server
docker port traefik_code_server
docker inspect traefik_code_server \
  --format '{{range $name, $settings := .NetworkSettings.Networks}}{{println $name}}{{end}}'
```

The first command must report `running` and `healthy`. The health endpoint must return JSON containing `"status":"alive"`, and the recent log must contain no startup, permission, authentication, extension, or workspace error. `docker port` must produce no output, and the network output must contain only `traefik-net`.

From a trusted client:

1. Confirm `code.<MY-DOMAIN>.com` resolves to the private reverse proxy address, not a public address.
2. Open `https://code.<MY-DOMAIN>.com` in a fresh private browser window.
3. Confirm the browser presents a valid certificate and Authelia requires the configured password and TOTP before code-server appears.
4. Open a file and the integrated terminal to prove the WebSocket-dependent editor session works.
5. Sign out of Authelia or open another private window and confirm the editor is protected again.
6. Confirm the router has no port-forward rule for `8443` and public DNS does not publish a code-server address.

From a trusted client terminal, confirm the LXC's internal application port is not reachable directly. The reference environment uses `192.168.0.102`; substitute the reverse proxy LXC address you selected if it differs. The command is expected to fail:

```sh
if curl --fail --silent --show-error --connect-timeout 3 \
  http://192.168.0.102:8443/healthz; then
  printf 'BLOCKING: code-server is reachable through a published host port.\n' >&2
  exit 1
else
  printf 'Expected: the direct LXC port is not reachable.\n'
fi
```

Finally, confirm the main security stack remains healthy in the reverse proxy LXC (**LXC → Console**):

```sh
docker inspect crowdsec authelia traefik \
  --format '{{.Name}} running={{.State.Running}} health={{.State.Health.Status}}'
docker logs --since 5m traefik |
  grep -Ei 'code-server|error|middleware|backend' || true
```

#### Verify Filesystem and Git Boundaries

Inspect every effective mount in the reverse proxy LXC (**LXC → Console**):

```sh
docker inspect traefik_code_server \
  --format '{{range .Mounts}}{{printf "%s -> %s rw=%t\n" .Source .Destination .RW}}{{end}}' |
  sort
```

The output must contain exactly these four read-write mappings:

- `/CODE-SERVER/config → /config`
- `/TRAEFIK/config → /workspace/traefik`
- `/CROWDSEC/config/acquis.d → /workspace/crowdsec/acquis.d`
- `/AUTHELIA/config/configuration.yml → /workspace/authelia/configuration.yml`

It must not contain `/TRAEFIK/acme`, `/TRAEFIK/secrets`, `/TRAEFIK/logs`, `/CROWDSEC/data`, the full `/AUTHELIA/config` directory, `/AUTHELIA/data`, `/AUTHELIA/secrets`, or `docker.sock`. Do not misreport the two approved writable configuration-directory mounts as individual files or read-only references.

Test the intended identity rather than relying on a default root `docker exec` shell:

```sh
docker exec --user 1000:1000 traefik_code_server sh -c '
  test "$(id -u)" -eq 1000
  test "$(id -g)" -eq 1000
  test -r /workspace/traefik
  test -w /workspace/traefik
  test -r /workspace/crowdsec/acquis.d
  test -w /workspace/crowdsec/acquis.d
  test -r /workspace/authelia/configuration.yml
  test -w /workspace/authelia/configuration.yml
'
```

Still in the reverse proxy LXC (**LXC → Console**), confirm that container initialization did not change the source ownership or mode:

```sh
stat -c '%a %u:%g %n' \
  /TRAEFIK/config \
  /CROWDSEC/config/acquis.d \
  /AUTHELIA/config/configuration.yml \
  /TRAEFIK/config/dynamic/gotify.yaml
```

Confirm sensitive host paths are absent inside the Docker container:

```sh
docker exec --user 1000:1000 traefik_code_server sh -c '
  for path in \
    /workspace/acme \
    /workspace/secrets \
    /workspace/logs \
    /workspace/crowdsec/data \
    /workspace/authelia/users_database.yml \
    /var/run/docker.sock; do
    if [ -e "$path" ]; then
      printf "Unexpected mounted path: %s\n" "$path" >&2
      exit 1
    fi
  done
'
```

Now test code-server's actual browser save behavior against both writable directory mounts and the writable file mount. First record the original checksums in the reverse proxy LXC (**LXC → Console**):

```sh
sha256sum \
  /AUTHELIA/config/configuration.yml \
  /TRAEFIK/config/dynamic/gotify.yaml \
  /CROWDSEC/config/acquis.d/traefik.yaml \
  > /tmp/code-server-save-test.sha256
```

In the code-server editor:

1. Add `# code-server save test` as a final line in `authelia/configuration.yml`, save manually, remove the line, and save again.
2. Repeat the reversible add/save/remove/save test in `traefik/dynamic/gotify.yaml`.
3. Repeat it in `crowdsec/acquis.d/traefik.yaml`.

Every save must succeed. A `Device or resource busy`, permission error, failed temporary-file rename, or changed source ownership is a blocking result; stop the stack and correct the source permissions without changing the approved identity or exposing additional host paths.

Back in the reverse proxy LXC (**LXC → Console**), prove that all three sources returned byte-for-byte to their original state and remain valid:

```sh
sha256sum --check /tmp/code-server-save-test.sha256
rm /tmp/code-server-save-test.sha256
stat -c '%a %u:%g %n' \
  /AUTHELIA/config/configuration.yml \
  /TRAEFIK/config/dynamic/gotify.yaml \
  /CROWDSEC/config/acquis.d/traefik.yaml
docker exec authelia authelia config validate --config /config/configuration.yml
docker exec crowdsec cscli version >/dev/null
docker exec traefik traefik healthcheck --ping
docker logs --since 2m traefik
```

The checksum checks must report `OK`, ownership must remain `1000:1000` with the established modes, and all three consumers must remain healthy without configuration or file-provider errors.

If the optional Traefik Git repository was initialized, verify it as the actual code-server identity:

```sh
docker exec --user 1000:1000 traefik_code_server sh -c '
  cd /workspace/traefik
  test "$(git branch --show-current)" = main
  test "$(git log -1 --pretty=%s)" = "Initial configuration"
  test -z "$(git status --porcelain)"
  test -z "$(git remote)"
  git check-ignore --no-index -q example.secret
  git ls-files
'
```

The tracked list must contain only `.gitignore`, `traefik.yaml`, and the reviewed `dynamic/*.yaml` files. The worktree must be clean, the example name ignored, and no remote configured. This test does not claim Git coverage for CrowdSec or Authelia.

In **Komodo → Stacks → code-server**, restart only the code-server container once. After it returns to `healthy`, reopen the private URL and confirm that `/workspace`, Auto Save `off`, workspace content, and any deliberately installed extension persist. If the optional Traefik Git history was configured, confirm that it persists too. Repeat the mount and identity commands above; the boundary must be unchanged.

Use **Komodo → Stacks → code-server → Redeploy** once with the same Compose definition. A redeploy deliberately starts/recreates the container. Repeat the health, workspace, optional Git, mount, and authentication checks, then continue to the final stop. Test an actual image update only when a reviewed new pin is available; after changing it, repeat this complete acceptance test and rollback if it fails.

#### Stop code-server Until Needed

After every running-state check passes, go to **Komodo → Stacks → code-server → Stop**. Stop only this stack.

In the reverse proxy LXC (**LXC → Console**), confirm the expected final state:

```sh
test -z "$(docker ps \
  --filter 'name=^/traefik_code_server$' \
  --format '{{.Names}}')"
docker ps -a \
  --filter 'name=^/traefik_code_server$' \
  --format 'name={{.Names}} status={{.Status}}'
docker inspect crowdsec authelia traefik \
  --format '{{.Name}} running={{.State.Running}} health={{.State.Health.Status}}'
```
