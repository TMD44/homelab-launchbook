# Setup Custom Domain

With AdGuard Home handling local DNS, the next step is to give the homelab services consistent private hostnames and prepare automatic HTTPS certificates. This chapter registers or connects a domain, creates a restricted Cloudflare API token, and adds the local wildcard DNS rewrite that the reverse proxy will use.

## About the Domain Setup

This guide uses addresses such as `https://traefik.<MY-DOMAIN>.com` and `https://adguard.<MY-DOMAIN>.com`. AdGuard Home resolves these names to the local reverse proxy at `192.168.0.102`, while Traefik obtains a publicly trusted wildcard certificate for `<MY-DOMAIN>.com`.

Traefik uses the [DNS-01 challenge](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge) to prove control of the domain. It temporarily creates a TXT record through the authoritative DNS provider's API, so certificate issuance does not require a public A or AAAA record, router port forwarding, or public access to ports `80` and `443`.

## Before You Begin

Before continuing, confirm that:

- AdGuard Home is installed and answering DNS queries as described in the [DNS Server](<3. Setup DNS Server.md>) chapter.
- You have access to the email account and Cloudflare account that will manage the domain, and the Cloudflare account email address is verified.
- Multi-factor authentication is enabled on the Cloudflare account, and its recovery codes are stored securely outside the homelab.
- You have a password manager for the DNS API token and a current payment method for domain registration or renewal.

If your home network does not use the `192.168.0.0/24` subnet, continue using the replacement addresses selected in the [Prerequisites](<0.0 Prerequisites.md>) chapter.

A domain is a long-lived dependency for private hostnames and certificate renewal. Keep the registrar and DNS-provider account details, recovery information, current contact addresses, expiration date, and renewal setting somewhere accessible even when the homelab is unavailable. Manage auto-renew deliberately, keep the provider's transfer or registrar lock enabled except during an intentional transfer, and review renewal notices. An expired or lost domain can break hostname resolution and future certificate renewal even though the applications remain on the local network.

## Add the Domain to Cloudflare

This section prepares the domain used for local service addresses and automated certificate validation. Cloudflare is the guide's reference registrar and authoritative DNS provider, so the primary path begins by registering a new domain there.

- Open the [Cloudflare dashboard](https://dash.cloudflare.com/) and sign in or create an account. Verify a new account's email address before attempting registration.

> **Important:** Domain registration is a paid service and normally renews for a recurring annual fee. Prices vary by top-level domain, so review both the initial registration price and the renewal price before purchasing.

- Go to the [**Register domains** page](https://dash.cloudflare.com/?to=%2F%3Aaccount%2Fregistrar%2Fregister).
- Search for the domain you want. Review the available top-level domains, choose an available result, and select **Purchase**.
- Select the registration term under **Payment option**. Confirm the displayed expiration date, total price, **Renew On** date, and auto-renew setting before continuing; Cloudflare enables auto-renew by default.
- Enter complete and accurate registrant contact details using ASCII characters and any additional format required by the selected top-level domain, then add or select the payment method.
- Review the registration agreements and privacy terms, then select **Complete purchase**.
- Check the account email for the purchase confirmation and any registrant-verification request. Complete required verification promptly so the domain is not placed on hold.
- Open the domain from the [**Manage domains** page](https://dash.cloudflare.com/?to=%2F%3Aaccount%2Fregistrar%2Fdomains) and confirm that its status is **Active**. Review its contact information, expiration date, auto-renew setting, and transfer-lock status before continuing.

If the domain is already registered elsewhere, it does not need to be transferred to Cloudflare Registrar. To use Cloudflare for authoritative DNS, follow Cloudflare's [primary DNS setup](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/): onboard the domain, review every imported DNS record, remove an existing DS record or disable DNSSEC before replacing the authoritative nameservers, update the nameservers at the current registrar, and wait for the zone to become **Active**. Preserve the previous DNS records and registrar access until the change is verified, because an incomplete nameserver migration can interrupt services already using the domain. Re-enable DNSSEC through Cloudflare after the new delegation is working if it was previously enabled.

As an optional delegation check, run this command from a terminal on a LAN workstation:

```sh
nslookup -type=NS <MY-DOMAIN>.com 1.1.1.1
```

The result should list the authoritative nameservers assigned to the domain. For the Cloudflare reference path, they are the nameservers shown in the Cloudflare dashboard. Resolve a mismatch before continuing.

Cloudflare is the documented reference provider, not a strict requirement. The registrar and authoritative DNS provider can be different, so readers who already own a domain may keep their current registrar while changing only DNS hosting. Traefik's [ACME DNS challenge documentation](https://doc.traefik.io/traefik/reference/install-configuration/tls/certificate-resolvers/acme/#dnschallenge) uses lego's [supported DNS providers](https://go-acme.github.io/lego/dns/); choosing another provider requires that provider's credentials and a matching change to the Reverse Proxy chapter's Cloudflare-specific configuration.

## Create a DNS API Token

Traefik needs a restricted credential to ask Cloudflare's DNS API to create and remove the temporary TXT records used by the ACME DNS-01 challenge. This allows certificate issuance and renewal to run automatically without exposing the homelab applications or opening inbound ports.

Cloudflare hosts the public DNS zone and can therefore process and manage its public DNS data, including temporary validation records. It does not automatically receive or proxy the private applications' HTTP or HTTPS traffic in this design because no public homelab A, AAAA, or CNAME record routes that traffic through Cloudflare. When Let's Encrypt issues the apex and wildcard certificate, those certificate names are published in [Certificate Transparency logs](https://letsencrypt.org/docs/ct-logs/), but individual service names covered only by the wildcard are not listed separately.

Use an API token instead of the Cloudflare Global API Key:

- In Cloudflare, go to **My Profile → API Tokens → Create Token → Create Custom Token**.
- Enter a descriptive token name such as `traefik-dns-challenge`.
- Add the following permissions:

| Scope | Resource | Permission |
| --- | --- | --- |
| Zone | Zone | Read |
| Zone | DNS | Edit |

- Under **Zone Resources**, select **Include → Specific zone → `<MY-DOMAIN>.com`**.
- Leave **Client IP Address Filtering** empty unless the reverse proxy uses a fixed public egress address that will be kept current. A changing home public address can otherwise prevent certificate renewal.
- Leave the token **TTL** unset for unattended renewal, or set an expiration only when a replacement is scheduled before that date.
- Select **Continue to summary**, confirm that the token applies only to the required zone, and create it.
- Copy the token immediately and store it in your password manager. Cloudflare will not display the secret again.

> **Important:** Anyone with this token can change DNS records in the selected zone. Do not paste it into a Markdown file, Compose environment field, command line, screenshot, or log. The next chapter stores it in a permission-restricted file.

The repository's Compose configuration mounts `/TRAEFIK/secrets/cf_dns_api_token` as a Docker secret and points Traefik to it through `CF_DNS_API_TOKEN_FILE`; `traefik.env` remains non-secret.

If the token is exposed, lost, or no longer needed, roll or revoke it under **My Profile → API Tokens**. After Traefik is deployed, place any replacement in the protected token file described in the next chapter and recreate the Traefik container so it mounts the replacement; do not leave the old token active.

## Create the Local Wildcard DNS Rewrite

The domain is now known, so AdGuard Home can direct every homelab hostname beneath it to the planned reverse proxy address. This DNS mapping can exist before Traefik is installed, but the services will not become reachable through these hostnames until the reverse proxy is configured in the next chapter.

- In AdGuard Home, go to **Filters → DNS rewrites → Add DNS rewrite**.
- Enter the following values:
  - **Domain name:** `*.<MY-DOMAIN>.com`
  - **IP address:** `192.168.0.102` (the reverse proxy LXC address)
- If the network plan uses a different reverse proxy address, enter that value instead.

Do not create a public wildcard A, AAAA, or CNAME record for the homelab. The AdGuard Home rewrite supplies the private records used by this guide, while Cloudflare needs only the public zone data and temporary DNS-01 TXT records required for certificate validation.

From a terminal on a LAN workstation, query AdGuard Home directly:

```sh
nslookup "traefik.<MY-DOMAIN>.com" 192.168.0.101
```

The answer must contain `192.168.0.102`, and the request should appear in AdGuard Home's **Query Log**. If the network plan uses different DNS or reverse proxy addresses, expect those values instead. This check proves only the local DNS mapping; browser access and HTTPS are verified after Traefik is deployed in the next chapter.

Keep the following values available:
